# kore-plugin-terminal — Плагин веб-терминала

## Что он делает

Это плагин веб-терминала для kore (id `terminal`). Каждый сеанс — это **настоящий PTY с
регистрационной оболочкой**, а не обёртка для выполнения команд: запись означает ввод с клавиатуры,
чтение — вывод терминала (включая управляющие последовательности), готовый к работе с фронтендом
вроде xterm.js. Начиная с 0.2.0 добавлены **разрешения на уровне методов**, **сохраняемая по сеансам
история команд** и **восстановление соединения** (возобновляемые курсоры чтения). Чисто визуальные
аспекты — размер шрифта, полноэкранный режим, темы и разделённые панели — не относятся к этому
репозиторию.

- Протокол: `kore.plugin.v1`, `lifecycle=resident` (терминал должен оставаться активным), уровень глубины `production`.
- Разрешения: `system:read` + `system:admin` + `proc:write`, с `method_capabilities` для каждого метода.
- Бюджет ресурсов: 12 МиБ памяти / 25% CPU / 64 pids.

## Реализация PTY (без сторонних библиотек)

`internal/terminal/pty_linux.go` использует только стандартную библиотеку и следует фиксированному
_linux_-порядку открытия псевдотерминала: открыть `/dev/ptmx`, разблокировать ведомый конец
(TIOCSPTLCK), получить номер ведомого (TIOCGPTN) и открыть `/dev/pts/<n>`, запустить регистрационную
оболочку с `Setsid` + `Setctty` (так что идентификатор группы процессов равен pid, что позволяет
`kill(-pgid)` завершить всё дерево при закрытии), изменить размер окна через `TIOCSWINSZ`.
Мастер-дескриптор неблокирующий, чтение/запись используют `select`, чтобы одна вставка не заблокировала
цикл. Платформы: сборка на `linux/amd64`, `linux/arm64`, `linux/riscv64` и `linux/loong64`; остальные
платформы явно возвращают `E_UNSUPPORTED`.

## Методы протокола (kore.plugin.v1)

| Метод | Вход | Описание |
| --- | --- | --- |
| `kore.ping` | `{}` | Живучесть и метрики времени выполнения |
| `kore.shutdown` | `{}` | Сохранить историю, закрыть все сеансы и корректно выйти |
| `terminal.create` | `{client_id?,cols?,rows?,shell?}` | По умолчанию 80x24, `/bin/bash`, `default` |
| `terminal.write` | `{session_id,client_id?,data}` | `data` в base64; ввод записывается в историю |
| `terminal.resize` | `{session_id,client_id?,cols,rows}` | Возвращает значение после применения `TIOCSWINSZ` |
| `terminal.read` | `{session_id,client_id?,cursor?,max_bytes?}` | Инкрементальное чтение; с `cursor` продолжает с него |
| `terminal.attach` | `{session_id,client_id?,cursor?}` | Переподключить живой сеанс, проверить восстанавливаемость курсора |
| `terminal.close` | `{session_id,client_id?}` | `kill(-pgid)` + закрыть fd + удалить из карты |
| `terminal.list` | `{client_id?}` | Без него: административный вид (все); с ним: фильтр по владельцу |
| `terminal.history` | `{session_id?,client_id?,limit?}` | Запрос истории команд (сначала новые) |
| `terminal.history.clear` | `{session_id?,client_id?}` | Очистить историю вызывающего |

**Кодирование данных**: `terminal.write.data`, `terminal.read.data` и `terminal.history.entries[].data`
используют стандартный base64 (с заполнением `=`) — вывод терминала может содержать произвольные
бинарные данные и многобайтовые последовательности UTF-8, разорванные между кадрами; при помещении
непосредственно в JSON они были бы молча заменены на U+FFFD. Фронтенд один раз декодирует их и
передаёт байты в `term.write(Uint8Array)`. Некорректный base64 возвращает `E_INVALID`.

## Владение сеансом и отклонение несанкционированного доступа

`terminal.create` может нести `client_id` (буквы/цифры/`-_.:@`, <=64 байт, по умолчанию `default`);
владение неизменно после создания. `write/read/resize/close/attach/history` должны нести тот же
`client_id`, иначе возвращают `E_UNAUTHORIZED`, не затрагивая сеанс владельца. **Модель доверия**:
`client_id` — логическая метка владения внутри плагина, а не аутентификационные данные; реальная
граница аутентификации — авторизация `method_capabilities` в ядре.

## Восстановление соединения и курсоры чтения

Каждый сеанс ведёт монотонно возрастающий абсолютный байтовый курсор `offset` (доставленные байты),
который сдвигается только чтением `read`. `cursor == offset` — инкрементальное чтение; `cursor < offset`
внутри окна повтора возвращает байты `[cursor, offset)` (`replay=true`); раньше нижней границы окна —
`E_CONFLICT`, позже — `E_INVALID`. Окно `KORE_TERMINAL_REPLAY_BYTES` по умолчанию 64 КиБ (макс. 4 МиБ)
и хранит только последние доставленные байты; повторное чтение того же курсора идемпотентно. Сеанс
живёт до явного закрытия, выхода оболочки или освобождения из-за простоя (по умолчанию 1800с,
вызывается лениво при обращениях, без таймера); после освобождения его нельзя восстановить —
`attach` возвращает `E_NOTFOUND`.

## История команд

Записывается только ввод `terminal.write`, группируется по сеансам и хранится в
`<KORE_STATE_DIR>/history/session-<id>.json` (каталог 0700, файл 0600, атомарная запись). Число
записей на сеанс (по умолчанию 200), байт на запись (по умолчанию 4096) и число сохраняемых сеансов
(по умолчанию 50) настраиваются; излишние удаляются от самых старых, слишком большие усекаются с
меткой `truncated`. Сохранение работает по принципу best-effort: ошибки не отклоняют ввод и честно
возвращаются через `terminal.history.storage_error`. При `KORE_TERMINAL_HISTORY=off` или отсутствии
`KORE_STATE_DIR` история отключается с WARN. **Конфиденциальность**: история может содержать введённые
пользователем пароли; плагин никогда не пишет ввод в логи, но вставлять пароли открытым текстом в
терминал по-прежнему не рекомендуется.

## Безопасность и ресурсы

Предел сеансов по умолчанию 4 (`KORE_TERMINAL_MAX_SESSIONS`, 1-16, превышение → `E_RATELIMIT`);
одно чтение/запись 1 МиБ, бюджет 5с на запрос; `shell` должен быть абсолютным путём к существующему
исполняемому файлу; из окружения дочерней оболочки удаляется `KORE_PLUGIN_TOKEN`, чтобы учётные
данные протокола не попали в терминал.

Переменные окружения: `KORE_TERMINAL_MAX_SESSIONS` (4), `KORE_TERMINAL_IDLE_SEC` (1800),
`KORE_TERMINAL_SHELL` (`/bin/bash`), `KORE_TERMINAL_REPLAY_BYTES` (65536),
`KORE_TERMINAL_HISTORY` (on), `KORE_TERMINAL_HISTORY_MAX` (200),
`KORE_TERMINAL_HISTORY_ENTRY_BYTES` (4096), `KORE_TERMINAL_HISTORY_SESSIONS` (50).

## Канал вывода: опрос, а не события

Вывод: опрашивать `terminal.read` (инкрементальное чтение) вместе с `attach`/`cursor` для
восстановления, а не использовать push-события: в протоколе нет зарегистрированного события
`terminal.output`, и ядро не передаёт события плагинов в SSE. Фронтенд может опрашивать каждые 30-80мс
или читать сразу после ввода.

## Установка и сборка

Автономный Go-модуль, зависящий только от `kore/pkg/pluginapi` и стандартной библиотеки; без
сторонних зависимостей и без фиксируемого в репозитории `go.work`. База сборки:
`CGO_ENABLED=0 GOWORK=off GOAMD64=v1 -trimpath -buildvcs=false -ldflags="-s -w"`.
Локальная проверка: `gofmt -l .`, `GOWORK=off go vet ./...`,
`GOWORK=off go test -count=1 -timeout 200s ./...`, `make dist` (побайтово воспроизводимая упаковка).
Артефакты релиза: `dist/terminal-<версия>.tar.gz` + `.sha256`. Не открывайте публичный issue для
уязвимостей — раскрывайте их приватно согласно
[SECURITY.md](https://github.com/kore-pl/kore-plugin-terminal/blob/main/SECURITY.md).
